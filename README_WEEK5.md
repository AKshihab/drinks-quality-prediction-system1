# Week 5 - MySQL Database and Midterm Prototype

## Objective

This Week 5 extension adds a reproducible, normalized MySQL/MariaDB database to the existing Drinks Quality Prediction System. It connects the canonical `week4_php_auth` PHP module to MySQL through PDO, replaces the Week 4 mock login with a database-backed login, and displays relational prediction history on the protected dashboard.

The implementation follows the Week 5 laboratory manual:

- Four interconnected tables in Third Normal Form (3NF)
- Primary keys, foreign keys, referential integrity, indexes, and seed data
- CRUD, INNER JOIN, LEFT JOIN, and aggregate SQL examples
- Mermaid ERD in the project SRS
- PDO prepared statements and `password_verify()`
- Existing PHP session protection, five-minute inactivity timeout, and complete logout
- XAMPP Apache, MySQL/MariaDB, and phpMyAdmin compatibility
- A five-minute midterm demonstration sequence

Supabase is not used. The Week 5 manual specifically requires MySQL/MariaDB and phpMyAdmin.

## Database design

Database name: `drinks_quality_db`

Character set: `utf8mb4`

Collation: `utf8mb4_unicode_ci`

Storage engine: `InnoDB`

Tables:

1. `users` stores each account once, including the unique email and PHP password hash.
2. `models` stores each model name, algorithm, version, optional verified accuracy, and active status once.
3. `drink_samples` stores all eleven physicochemical inputs and links each sample to its submitting user.
4. `predictions` links a sample to the model used and stores the result, label, and time.

Relationships:

- `users.user_id` -> `drink_samples.user_id` is one-to-many.
- `drink_samples.sample_id` -> `predictions.sample_id` is one-to-many.
- `models.model_id` -> `predictions.model_id` is one-to-many.

The ERD and normalization explanation are in `project-docs/Project_SRS.md` under **Week 5 Database Design**.

The schema is in 3NF because every non-key column depends on the primary key of its own table and not on another non-key column. User information and model information are not duplicated in prediction records.

## Check the database and relationships

Run these commands in phpMyAdmin's SQL tab:

```sql
USE drinks_quality_db;
SHOW TABLES;
SHOW CREATE TABLE predictions;

SELECT * FROM users;
SELECT * FROM models;
SELECT * FROM drink_samples;
SELECT * FROM predictions;
```

In phpMyAdmin, select the database, open **Designer**, and check these links:

- `drink_samples.user_id` -> `users.user_id`
- `predictions.sample_id` -> `drink_samples.sample_id`
- `predictions.model_id` -> `models.model_id`

Main four-table JOIN:

```sql
SELECT
    p.prediction_id,
    u.full_name,
    u.email,
    ds.sample_id,
    ds.alcohol,
    ds.ph,
    p.predicted_quality,
    p.quality_label,
    m.model_name,
    m.algorithm,
    p.created_at AS prediction_date
FROM predictions AS p
INNER JOIN drink_samples AS ds
    ON p.sample_id = ds.sample_id
INNER JOIN users AS u
    ON ds.user_id = u.user_id
INNER JOIN models AS m
    ON p.model_id = m.model_id
ORDER BY p.created_at DESC;
```

## Troubleshooting

### Apache does not start

Another program may be using ports 80 or 443. Open XAMPP logs, stop the conflicting web server, or configure Apache to use an available port. Use the port in the localhost URL if it is changed.

### MySQL does not start

Another MySQL/MariaDB service may be using port 3306. Stop the conflicting service or update both MySQL and `week4_php_auth/config/db.php` to use the same port.

### `Unknown database 'drinks_quality_db'`

Import `database/schema.sql` in phpMyAdmin, then retry the login or PDO connection test.

### `Access denied for user 'root'`

The file assumes XAMPP's default empty root password. If a local root password was configured, update only the local `$database_password` value in `week4_php_auth/config/db.php`. Do not commit a real remote password.

### `could not find driver`

Open `C:\xampp\php\php.ini`, ensure the `pdo_mysql` extension is enabled, restart Apache, and run `C:\xampp\php\php.exe -m` to confirm `pdo_mysql` appears.

### Page not found or PHP source appears as text

Confirm Apache is green, the folder exists at `C:\xampp\htdocs\drinks-quality-prediction-system1\week4_php_auth`, and the browser URL begins with `http://localhost/`.

### Login always fails

Confirm the schema was imported, use the exact demonstration credentials, and run:

```sql
USE drinks_quality_db;
SELECT user_id, full_name, email, role FROM users;
```

Never replace `password_verify()` with a plain-text password comparison.

### Dashboard shows a safe database error

Start MySQL, confirm `drinks_quality_db` exists, and run the connection check. Detailed connection/query errors go to the PHP error log; browser users receive only a safe message.
